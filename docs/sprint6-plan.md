## Scope and priority

P0 remains one reliable journey from an actual photograph through selected vision inference, human correction, preference-aware owned-item styling, saved look, wear history and undo. The user subsequently requested independent OpenAI recognition/styling providers, model profiles, a document vector library, explicit personal preferences and recommendation tracking. Those extensions now have implementation paths in the current working tree. Keep the initial local journey as the comparison and recovery path; verify the advanced path before claiming improved speed or quality. Quest XP is a short optional extension in the proposed five-minute demo. Inspiration and resale remain secondary.

The advanced architecture keeps React and the Node API, adds provider adapters and SQLite passage/vector persistence, and preserves model-independent validation. The previous dominant observed wait was inference; changing frontend/backend language alone has no demonstrated speed benefit. Fast/Balanced/Deep are OpenAI model selections, not fine-tuning. Feedback changes bounded retrieval scores. Wardrobe UUID namespaces are organizational isolation, not authentication or authorization.

The September 17 technical design is a target architecture, not proof of implementation. It refers to an earlier MVP Must Have list but does not reproduce a separately labeled complete list. ## Next-sprint order

1. Account/storage foundation and deletion/export recovery before any private-data hosting. Add cross-user access denial and restart tests.
2. Recognition/provider latency and queue UX: cold/warm/cache-separated profiling, warm-up indicator, bounded wait/cancel, cost and quality comparison on held-out photos. Target the original <20s/90% threshold with a meaningful sample; validate the new adapters before expanding model choices.
3. Human styling acceptance and occasion precision: independent photos and blinded top-three choices; measure correction burden, suitability and failure rate. An ID validator does not guarantee good taste.
4. Automate browser/document persistence and recovery, backup import, quota handling, multi-tab writes, complete namespace deletion, and index migrations. Verify physical camera and downloaded exports on the presentation browser. Persisted SQLite documents need an explicit retention policy.
5. Only after the above: authenticated deployment, approved resale adapter verification, richer image matching and fine-tuning on eligible consented data.
